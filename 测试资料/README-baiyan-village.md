# 百岩村｜据点推演测试

[打开百岩村推演网页](baiyan-village.html)。百岩村用于验证据点怎样在玩家介入前后继续运作。玩家可以经营自己的据点，借据点发展势力，也可以通过跑团、交涉和资源调度影响已有聚居地。

## 设计原则

- 新增属性或联动，要能扩大玩家行动的影响，加强据点的真实感和可玩性。先说明玩家可以做什么、哪项局势会因此变化，以及变化如何进入后续经营或跑团。
- 定性选择也可以产生完整的叙事后果。例如「恢复通路」使待命的援粮可以按期到达，「分布式采掘」使矿业在震荡期间维持生产。玩家可以直接选择行动、承诺和优先事项，后台据此结算。
- 据点可以在玩家缺席时依照预案继续运作。周报、月报和重大事件消息是主要反馈。只有当前预案无法覆盖、需要玩家做出有意义的选择时，才要求玩家介入。
- 用已有属性和通用流程表达新情况。新增一项数据前，检查它是否提供了新的行动、可感知的后果或必要的结算依据，也要考虑对玩家注意力、主持人工作量和系统运算的代价。
- 玩家侧以定性信息为主，例如粮食吃紧、守备空虚或援粮预计下周到达。后台数据用于调试、解释结果和统一结算。

## 结算精度与玩家所见

精细化用于维持结算稳定、保留属性之间的联动，并让同一项干预能在后续经营和跑团中产生可追溯的效果。后台保留必要的精度和零头，资源批和人口组用于展示、调度与对账。

模糊化用于减轻游玩压力。玩家通常从描述、告示和实地观察判断局势。角色具备相关能力并主动调查时，可以看到与该能力相符的更细信息，例如库存还能支撑多久、工坊缺哪类劳力、哪处防御最薄弱。可见程度随能力和掌握的情报变化。

定性信息也足够支持有效行动。玩家可以直接针对感受到的问题提出办法。例如发现口粮不稳后，可以护送商队，也可以尝试以神秘仪式培育能持续产粮的植物。主持人确认这种行动在故事中成立后，系统可将它接入既有的持续产出和库存结算。这里的植物是干预示例，具体能力、条件与产量待定。

## 货币、资源与单位

统一据点交易、仓储、运输和消耗的记账口径。货币使用共同的计价单位，实物流转使用各自的资源单位。以矿换粮时，按矿产单位交付，按口粮单位入库。货币用于报价和结算，实物账保留缺粮、运输中断和补给延误等实际约束。

- **货币单位**用于报价、税费和支付。正式名称、面额及换算待定。
- **资源单位**按物资类别记录，例如口粮、矿产和造物各用本类单位。同一资源的产出、贸易、运输、库存和消耗沿用同一口径。
- **人口单位**代表成组居民，可区分劳动力和非劳动力。日常经营可按成组人口处理产出、口粮、伤亡和迁移。涉及具名角色、具体护送对象或特定伤亡时，按剧情记录实际人员。
- 口粮可以按一批可供据点调度的补给计量。玩家可以看到「还能撑到下次商队」或「本周需追加一批口粮」这类信息。人口单位、口粮单位如何对应，以及零散变化何时计入单位，留待测试。

## 原型状态

当前网页的玩家视图以定性描述为主。后台按人口组和资源批展示并调整，内部保留不足一组或一批的余额。测试换算为每组约 10 人，每批口粮 100 份、矿石 20 筐、造物 5 件。矿井塌方与盗匪袭扰按周判定，商队按月结算。正式换算与货币面额待定。

## 灾难缓冲试场

打开 [百岩村推演网页](baiyan-village.html)，分别开始「无人介入」和「玩家救援」对照。两条路线使用同一场岩壁崩裂。点击「推进一个反应步」，可查看预警、当地停时、反应期倒计时和待企划确认的结果。救援路线在反应期内点击「组织救援」。

- **无人介入。** 出入口与主要补给通路失效，百岩村可能被弃置或消亡。
- **及时救援。** 临时通道接通，避难和补给具备可行条件，建议暂缓判定百岩村消亡。

试场可并排展示两条结果，村庄及具名 NPC 的去向均待企划裁定。预警 **1 个现实日步**、反应期 **2 个现实日步**均为临时参数。时钟追赶和回溯留待讨论。试场独立运行，常规经营使用自己的村况记录。
