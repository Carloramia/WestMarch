# 外境 NPC 编辑器原型

双击同目录的 index.html，或用 Microsoft Edge 打开。页面可离线运行。切换右上角的 NPC 策划、玩家创建与玩家换装，查看同一份外观在不同权限下的表现。保存配方可导出 JSON，预览可导出 PNG。

## 如何验证

1. 策划模式加斜疤，再戴半面罩。摘下面罩后疤应重新出现。加肩部骨甲与额外双臂，切换站姿、移动和脸部近景。
2. 切到玩家创建，选择天然瞳色、发色和性别标识，完成创建。换装模式保留基础身份，可换前后发、妆容、染发、美瞳和衣物。换装模式加载其他配方时只应用日常造型。NPC 策划模式可载入完整配方。
3. 在本地姿势样本区选一个包含 ModInfo.Xml 和 ClothCustom 的《废墟图书馆》工坊角色目录。在本机可选的一个实例见下文。导入后切换姿势可查看原图及方向、轴心和头部挂点字段。本地样本负责核对原格式，编辑器绘制用独立占位部件。

## 本机资源盘点

资源容器盘点.csv 记录三套安装目录的匹配路径、字节数和已读签名。此表以安装目录为边界。

- 废墟图书馆共 752 条容器与 StreamingAssets 记录。char 目录 736 个包，另有 card_art.pres。737 个 .pres 头部均为 UnityFS。这些记录是包级清单，包内角色对象仍待索引。
- 本机工坊样本位于 Steam 安装下 steamapps/workshop/content/1256670/2884559316/Resource/CharacterSkin/AyinPlayer。含 10 张 ClothCustom PNG 和姿势 XML。Default 的方向为 Front，轴心为 (41, -400)，样本关闭独立头部。Move 轴心为 (35, -386)。原点随姿势变化这一点已纳入原型的姿势设计。资源预览显示原数值，坐标轴方向和单位暂由读取方核实。
- 边狱巴士共 1777 条，其中 1735 条是 .bank。确认 StreamingAssets/aa/catalog.bin、catalog.hash、本地字体 / FMOD / ScriptableObject 三个 .bundle，以及 Unity serialized assets。具体身份的姿势图、纹理及动画引用尚未从包内定位。
- 脑叶公司共 25 条匹配记录，主要是 Unity serialized assets 及旁路文件。员工头部、装备和动作映射待确认。

工坊 PNG 由使用者通过浏览器选择，原型目录仅包含独立绘制的预览、文件级清单与本说明。核验结果适用于当前安装文件。

## 设计边界

基础身份的锁定是编辑器流程开关。性别标识与体型分别记录。途径件的有无由 NPC 策划模式控制；疤痕作为遮挡图层，肩甲在身体区域绘制，额外肢体在体型与姿势变换下绘制。实际途径映射待作者定义。骨骼、权重、关节动画留到后续，当前两个姿势用于验证拼接稳定性。

外部技术对照：[Project Moon 官方更新](https://store.steampowered.com/news/posts/?appids=1256670&enddate=1592561937)、[Universal LPC 部件规范](https://github.com/LiberatedPixelCup/Universal-LPC-Spritesheet-Character-Generator/blob/master/CONTRIBUTING.md)、[Unity Sprite Swap](https://docs.unity.cn/Packages/com.unity.2d.animation%409.0/manual/SpriteSwapIntro.html)。

## 本机图书馆贴图预览

首页默认读取本机 Steam 工坊的 Ayin 全身姿势 PNG。可切换五个姿势，或进入头部拼接，查看同一素材中的底头、表情和前发，并切换表情或隐藏前发。全身是工坊已合成的姿势图，头部视图验证分层。外境配方预览可从来源下拉切回。贴图引用指向本机工坊目录，未把源图复制到项目。现阶段使用的是工坊资源，游戏本体 UnityFS 中的贴图仍待导出与索引。

## 本机解包结果

本轮仅处理本机 Unity 包、序列化资源与场景对象。对每个可读对象记录来源包、序列化文件、Path ID、类型和名称，导出有有效图像的 Sprite 与 Texture2D；音频、可执行文件及未落盘的远程包不在图像导出范围内。解包采用 UnityPy 1.25.4。输出在 .local-unpacked，依赖在 .local-unity-reader，两目录由 Git 忽略。

| 游戏 | 可读本机包与场景 | 索引对象 | Sprite PNG | Texture2D PNG |
|---|---:|---:|---:|---:|
| 废墟图书馆 | 748 / 748 | 518,418 | 26,933 | 9,180 |
| 脑叶公司 | 33 / 33 | 348,806 | 7,464 | 4,043 |
| 边狱巴士 | 36 / 36（含补跑） | 791,667 | 7,124 | 1,611 |

边狱巴士的 3 个本地 Addressables 包首次缺少 Unity 版本字段，使用游戏自身的 6000.3.12f1 作为回退版本后均读通，补跑结果位于 .local-unpacked/retry/limbus。若看首跑 issues.json，这三条已恢复。边狱巴士目录字符串扫描提取出 3,191 个不同包名，仅 3 个匹配安装目录内的包。游戏自带清缓存脚本指定的 LocalLow Unity 缓存路径不存在。其余 3,188 个包名只能做缺失索引，暂无法确认每个包的内容。

逐个复查导出异常：废墟图书馆的 126 个 Sprite 的渲染矩形面积为零；三作另有 54 个零尺寸、无内嵌数据、无外部数据路径的 Font Texture。上表 PNG 计数与实际文件数一致。

### 可用于下一轮评估的原版拼接数据

- .local-unpacked/ruina/appearance_parts.csv 包含 610 个原版头部相关 Sprite，已逐个核对导出的 PNG 存在。覆盖头部、前发、后发、眼、眉、嘴、发饰，并记录方向、图集 Path ID、原始图块、实际纹理矩形、裁切偏移、轴心和缩放。样例的逻辑图块是 512 × 512，实际眼睛 PNG 可只有 94 × 28，后续还原应保留裁切偏移。
- .local-unpacked/ruina/pose_components.csv 从 736 个角色包提取 63,388 条 Transform、RectTransform、SpriteRenderer 关联，记录姿势物体、父级、局部位置与缩放、Sprite 引用及绘制顺序。char_1.pres 中普通、防御、受击和远程攻击以不同 SpriteRenderer 指向同包姿势贴图，普通姿势的两个物体共用一个 Sprite。本次是资源引用索引，未推导完整运行时状态机。
- 本轮未改 index.html。边狱巴士未落盘包，以及脑叶公司员工脸与装备跨对象的完整映射仍是待查项。

## 原版捏脸预览

首页默认使用本机《废墟图书馆》原版头部 Sprite。索引从已核对的 610 个头部件里选择 335 个具有明确命名与方向的条目，包含两张底头。其余条目保留在解包目录供后续辨认。可换前后发、眼、眉和嘴，选择正侧视与表情。后发若有前置层也一并绘制。界面按原轴心和裁切偏移放置贴图。原版素材中的侧面眉嘴只检出攻击版本，其他表情可回退至同款侧面攻击件并提示；没有同款侧面部件时显示缺项。

保存配方会写入原版部件 ID。NPC 策划可改全套，玩家创建可定五官，完成后换装仍可换前后发。原版预览同时支持头部与整套服装。途径附加件仍在外境配方预览中。

Edge 实测通过 8 项：原图成功解码、眼部切换、侧头选择、侧面缺件回退、正面受击表情、创建锁定、换装导入保留五官及导出原版部件 ID。

若需从已解包数据重建本机索引，使用含 Pillow 的 Python 环境运行同目录的 build_ruina_preview.py。输入和输出均在 .local-unpacked/ruina，贴图与浏览器索引留在本机。


### 原版服装

全身预览默认启用，提供五套从原版角色包挑出的独立身体 Sprite。头部部件和服装独立选择，同一配方保存两个部分。以各身体图预览校准领口上的头部挂点。首版服装以整套为单位，预览使用固定身体姿势，正侧方向与表情控制头部。PNG 和生成的索引留在本机解包目录。

Edge 更新后实测通过 11 项，包括五套服装可选、换衣后原版脸层路径不变、全身与脸部近景切换、五官锁定，以及服装 ID 的保存和换装导入。

## 美术资源估算与边狱巴士对照

以可选款式计，当前《废墟图书馆》原型有 44 款前发、23 款同时有正侧面的基础后发、32 款眼、14 款眉、14 款嘴、5 套服装和一套通用底头。一些后发具有额外前置层；一个款式也可能分朝向或表情。当前接入总数是 340 个索引项，含 5 套固定姿势的服装。

建议用 86 项单视角规格做《外境》第一轮原创定量样本：

| 类别 | 数量 | 交付口径 |
|---|---:|---|
| 底头 | 2 | 两种轮廓共用眼、眉、嘴锚点 |
| 前发／后发 | 12／10 | 每款基本一层，复杂发型的前置层另计 |
| 眼／眉／嘴 | 8／8／10 | 眼型与瞳色拆开，颜色走可染区域 |
| 疤痕／妆容 | 8／4 | 透明贴花，双向非对称疤痕按同一侧身份标注 |
| 整套服装 | 12 | 固定姿势、每套一张完整身体图与领口锚点 |
| 配饰 | 6 | 包含会遮脸、遮头发的件 |
| 途径附加件 | 6 | 示例为三组骨甲和三组非标准附加件，具体造型由作者决定 |

86 指基础条目，不含额外发层、肤色与染色遮罩，也不含换姿势和绑定。增加相同数量的正侧面对应图时，两视角基线为 172 个，按可复用贴花等调整为约 150–175 张。以同样 12 套服装做待机、移动、防御、受击、攻击五个整套姿势，共 60 张身体图；比一姿势增加 48 张。另外按需要补脸部表情及锚点。若走共享骨架，衣装可按 8–14 个图层估量，每套仍需适配到同一骨架并逐姿势检查，动作数从衣装数量中独立计算。

一名具备技能的 2D 角色美术，风格和模板已确定的情况下，第一轮 86 项单视角约 15–25 人日，正侧面约 25–40 人日。估算含部件绘制、基础锚点和混搭验收，排除绑定、动画、重做美术方向。先用少量成品测绘制速度再签正式排期。

来源下拉可在「废墟图书馆 · 捏脸与换装」和「边狱巴士 · 战斗美术对照」之间切换。第二个入口有罗佳与浮士德待机、卡米尔部件、以实玛利动作表四个公开参考，图片按远程链接显示，源素材没有复制进项目。Edge 验证了切换来源、切换样本和返回后保留外观配方。本机边狱巴士 Unity 缓存复查只含 __info，仍未取得能组装的战斗身份分层包，所以第二套目前用于美术对照。

## 边狱巴士补下载后的 Unity 缓存

Steam 修复下载完成后，LocalLow 下的 ProjectMoon_LimbusCompany 缓存出现 1,592 个 __data。已通过 index_limbus_cache.py 只读扫描。1,592 个包均可解析，共索引 1,747,581 个 Unity 对象，找到 858 条不同的 SD prefab 路径。九条入口为零 Path ID 引用，独立记录在 issues.json。索引目录为 .local-unpacked/limbus-cache。

export_limbus_samples.py 沿四个实际战斗 prefab 的 SpinePivot 和 SkeletonData 引用导出了浮士德（10201、10204）、良秀（10401）、罗佳（10901）的 Spine 4.0.64 骨架、图集文本及真实纹理页，位于该目录的 samples。四组骨架 JSON 和 PNG 文件均已复核。贴图留在本机缓存输出。

- 基础浮士德为 10 个 slot，良秀 8 个，握紧之人浮士德 31 个，罗佳 11 个。四者均有独立 head，但这四组待机骨架里未见单独眼、眉、嘴 slot。罗佳有多个独立前后发 slot。良秀单独拆了 top、bot 和外套前后件。握紧之人浮士德细分了小腿、大腿、手、肩甲等，装备间的骨骼和 slot 兼容性需单独验证。
- 导出的是默认 Spine 资源，未补导独立攻击时间线与其他 Animator/SpriteRenderer 部件。部分 atlas 声明画幅与 Unity 面板的实际纹理分辨率不同，不能直接把原画幅坐标当作导出 PNG 像素坐标。保留原始文本与实际尺寸，待验证 Unity 运行时的坐标转换。

## 边狱巴士可编辑预览

首页默认显示「边狱巴士 · 捏脸与换装」。服装与头部可独立选择，头部按原服装的头部区域对齐。可在全身或脸部近景里切换独立发层、控制可分离外衣和武器、叠加疤痕，并导出当前构图的透明 PNG。保存角色时两套游戏的配方独立记录。玩家创建后锁头部，换装仍可改服装和发层；途径疤痕由策划模式控制。

在 155 个已定位的人格编号里，86 套通过静态分层生成。另 69 套的状态见 .local-unpacked/limbus-cache/editor/preview_issues.json，主要是没有可确认的 head 槽、骨骼采用当前静态拼接器未处理的继承模式，或有裁剪附件。浏览器默认使用基础浮士德。四组人工查看的基础组合为浮士德、良秀、握紧之人浮士德、罗佳。跨服装头部对齐按包围框近似，特殊头饰及极端体型需要单独校正。发层、武器和外衣是否可拆取决于源 slot。五官随整头切换，专用动作、实时骨骼和眼眉嘴独立换件仍需独立美术与动画工作。

Edge 通过 13 项检查，包括 86 套选择、原图加载、换衣保留头、换头、发层隐藏、外衣武器拆卸、疤痕、头部近景、玩家锁定、配方回读和透明 PNG 编码，以及回切图书馆模式。

缓存索引使用 index_limbus_cache.py。export_limbus_samples.py 加 --all-prefabs 搜索 SD prefab 的默认模型；使用 --retry 只重试报告中的失败项。build_limbus_preview.py 可用 --identities 指向人格导出目录生成编辑器索引。原图及生成的浏览器预览部件保存在 Git 忽略的 .local-unpacked 下。

已逐个检查全部 858 个 SD prefab 路径。默认模型导出成功 827 份，其中 796 份 Spine 模型与 31 份默认 SpriteRenderer 静态图。其余 31 条在两个默认入口均未定位到可见模型，详见 .local-unpacked/limbus-cache/sd-exports/spine_samples.json。已核对清单里所有成功输出的路径存在，并验证 86 套编辑器图层 PNG。
